How to verify the reported results of version 3: a quick check that needs no accounts, and the full path through Earth Engine

5Level B: full path through Earth Engine

Earth Engine outputs go to a folder rep, which Git ignores, so they can be compared with the stored tables.

B1 Feature tables (about 30 minutes)

python scripts/gee_features.py --project YOUR-PROJECT-ID --out rep/features
python scripts/gee_features.py --project YOUR-PROJECT-ID --out rep/features_v2 `
    --points data/samples/points_v2_background.csv
python scripts/gee_features.py --project YOUR-PROJECT-ID --stack extra --out rep/features_v3/main
python scripts/gee_features.py --project YOUR-PROJECT-ID --stack extra `
    --out rep/features_v3/background --points data/samples/points_v2_background.csv

python scripts/compare_tables.py data/features/features.csv rep/features/features.csv
python scripts/compare_tables.py data/features_v2/features.csv rep/features_v2/features.csv
python scripts/compare_tables.py data/features_v3/main/features.csv rep/features_v3/main/features.csv
python scripts/compare_tables.py data/features_v3/background/features.csv rep/features_v3/background/features.csv

compare_tables.py matches rows by point_id and prints, per column, how many points differ and the largest difference. Google reprocesses its archives from time to time, so a few small differences are possible. To retrain on your own tables, repeat A2 with rep/ in place of data/ in the four table paths and --out rep/results_v3.

B2 Gujarat rasters (1 to 3 hours, mostly waiting; up to 12 GB)

python scripts/gee_export_gujarat.py --project YOUR-PROJECT-ID --boxes labels/gujarat_boxes.json
python scripts/gee_export_gujarat.py --project YOUR-PROJECT-ID --boxes labels/gujarat_boxes.json `
    --stack extra
python scripts/gee_export_gujarat.py --project YOUR-PROJECT-ID --status

When the tasks are complete, download the 14 files gujarat_<city>.tif from the Drive folder landfill_gujarat into data\gujarat\ and the 14 files gujaratx_<city>.tif into data\gujarat_x\. The rasters are not in the repository because of their size.

7Departures and limits a grader should know

  • The test is not blind for versions 2 and 3. They were designed after earlier Gujarat results were seen, and the same 17 sites have been scored three times. Only version 1 is a first-time test. No Gujarat pixel, and none of the false alarms checked there, was used in training.
  • One pin was removed from the sealed list after sealing. Surat LF-3 had no outline and was never scored; its row was deleted from gujarat_test_sites.csv on 15 November. The Surat box had been drawn with it, which is why the boxes are read from labels/gujarat_boxes.json and not recomputed.
  • Surendranagar is outside the design. It was added on 15 November as one unseen site and is reported separately from the 17.
  • Two scripts changed after freeze-v3, to make a rerun possible from the main branch: the export gained the --boxes option, and the freeze check in the scoring script now accepts an earlier tag when the model file is unchanged. git diff freeze-v3 HEAD -- scripts/score_gujarat.py shows that the scoring itself is untouched.
  • Only about 6% of Gujarat was scored, all of it within 15 km of a known site.
  • Alarm verdicts are one person's reading of Google Earth imagery. There was no field visit.
  • Earth Engine is not a fixed archive. A refetch can differ slightly from the stored tables.
  • Reproduction was tested on one machine. Steps A1 to A4 were rerun on the Linux machine that produced the stored files and reproduced them byte for byte. No Windows rerun was made; last-digit differences are possible there, most likely for logistic regression.
